# Roblox V-Breaker: Project Structure & Developer Guide

ยินดีต้อนรับนักพัฒนาทุกท่าน! เอกสารฉบับนี้จัดทำขึ้นเพื่อให้ทุกคนเข้าใจโครงสร้างของโปรเจกต์ **Roblox V-Breaker** และสามารถเข้ามาพัฒนาต่อได้อย่างราบรื่น

โปรเจกต์นี้ใช้ **Rojo** ในการจัดการซอร์สโค้ดภายนอก Roblox Studio ทำให้เราสามารถใช้ Git ในการทำ Version Control และใช้โปรแกรม Text Editor ภายนอก (เช่น VS Code หรือ Cursor) ในการเขียนโค้ดได้อย่างมีประสิทธิภาพ

---

## 📂 โครงสร้างโฟลเดอร์หลัก (Root Structure)

- `src/`: โฟลเดอร์ที่เก็บโค้ด Lua ทั้งหมดของเกม (แบ่งตามฝั่ง Client, Server, และ Shared)
- `Game-Design-Document/`: เก็บเอกสารอ้างอิงทั้งหมด ทั้ง GDD หลัก, บันทึกการพัฒนา, แผนการทดสอบ ฯลฯ
- `.agents/skills/`: เก็บคำสั่ง (Skills) สำหรับ AI Assistant (Antigravity/KI) เพื่อช่วยควบคุมมาตรฐานการเขียนโค้ด
- `default.project.json`: ไฟล์ตั้งค่าหลักของ Rojo ที่ระบุว่าโฟลเดอร์ไหนจะถูกดึงไปไว้ที่ไหนใน Roblox Studio
- `aftman.toml`: สำหรับจัดการเวอร์ชันของเครื่องมือต่างๆ (เช่น Rojo, Selene, Stylua)

---

## 🛠 สถาปัตยกรรมโค้ด (The `src` Directory)

โครงสร้างการเขียนโค้ดของโปรเจกต์นี้ แบ่งออกเป็น 3 ส่วนหลักอย่างชัดเจน:

### 1. `src/server` (ทำงานฝั่งเซิร์ฟเวอร์เท่านั้น)
โค้ดในโฟลเดอร์นี้จะถูก Sync ไปที่ **ServerScriptService**
- `ServerMain.server.lua`: จุดเริ่มต้น (Entry Point) ของฝั่งเซิร์ฟเวอร์
- `services/`: โฟลเดอร์ย่อยสำหรับเก็บ ModuleScript ที่จัดการระบบเบื้องหลัง (เช่น DataStore, การคำนวณดาเมจ, ระบบจัดการผู้เล่น)

### 2. `src/client` (ทำงานฝั่งผู้เล่นเท่านั้น)
โค้ดในโฟลเดอร์นี้จะถูก Sync ไปที่ **StarterPlayerScripts** (หรือใน PlayerGui)
- `ClientMain.client.lua`: จุดเริ่มต้น (Entry Point) ของฝั่งไคลเอนต์
- `controllers/`: เก็บ ModuleScript ที่รับข้อมูลจากเซิร์ฟเวอร์และควบคุมการแสดงผลให้ผู้เล่น
- `ui/`: เก็บโค้ดเกี่ยวกับการจัดการ User Interface (GUI) ต่างๆ

### 3. `src/shared` (ทำงานได้ทั้ง Server และ Client)
โค้ดในโฟลเดอร์นี้จะถูก Sync ไปที่ **ReplicatedStorage**
- `constants/`: เก็บค่าคงที่ (Constants) ที่ใช้ร่วมกัน เช่น ตัวแปรการตั้งค่าเกม, สเตตัสเริ่มต้น
- `network/`: เก็บโค้ดหรือ Module ที่เกี่ยวข้องกับการสื่อสารระหว่าง Server กับ Client (เช่น RemoteEvent / RemoteFunction)

*(หมายเหตุ: หากมีการดึง SharedModules จากโปรเจกต์ส่วนกลาง มันจะถูกเพิ่มเข้ามาใน ReplicatedStorage ผ่านไฟล์ `default.project.json` ด้วย)*

## 🤖 การทำงานร่วมกับ AI (AI Assistant)

โปรเจกต์นี้รองรับการพัฒนาแบบ **Agentic Coding** โดยมี AI ช่วยเขียนโค้ดและจัดการระบบ:

- **AI Skills (`.agents/skills/`):** นักพัฒนาสามารถดูทักษะที่ AI ถูกสอนไว้ได้ในโฟลเดอร์นี้ เช่น กฎการเขียน Lua, การทำ Animation, การทำ UI เป็นต้น
- **การแชร์ความรู้:** หากสร้างระบบใหม่เสร็จแล้ว แนะนำให้สร้างเอกสารสรุประบบนั้นๆ เก็บไว้ใน `_Knowledge` (ถ้ามี) หรืออัปเดตลงในเอกสาร GDD เพื่อให้ AI สามารถนำไปอ้างอิงในการสร้างระบบอื่นต่อได้

## 📝 ข้อตกลงและแนวทางปฏิบัติ (Best Practices)

1. **ห้ามแก้ไขโค้ดผ่าน Roblox Studio โดยตรง (ถ้าไม่จำเป็น):** 
   ให้แก้ไขใน `src` ผ่าน VS Code แล้วปล่อยให้ Rojo จัดการ Sync โค้ดเข้าไป เพื่อป้องกันการเกิด Conflict ใน Git
2. **แยกการทำงาน (Separation of Concerns):** 
   เซิร์ฟเวอร์จัดการข้อมูลและความปลอดภัย (Server-side Validation) ไคลเอนต์จัดการแค่การแสดงผลและการรับคำสั่งจากผู้เล่น
3. **การสื่อสาร (Networking):** 
   ลดการใช้ RemoteEvent พร่ำเพรื่อ ควรส่งข้อมูลเฉพาะเมื่อจำเป็นเพื่อป้องกันปัญหาเรื่อง Bandwidth และความล่าช้า (Lag)
